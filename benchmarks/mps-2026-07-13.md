# MPS推論高速化ベンチマーク（2026-07-13）

## 結論

Apple M4 Pro上で、実製品が使う4モデル・5推論を対象に改善した。

- 最終版の既定経路は、15秒のwarm推論合計が **19.793秒 → 16.200秒**。**18.15%短縮、1.222倍**。
- 長尺向けregional compileを有効にすると、同じwarm推論合計は **14.021秒**。初期比 **29.16%短縮、1.412倍**。
- 各段の出力を次段へ渡す34.44秒の実チェーンは、ロード込み **44.045秒 → 33.100秒**。**24.85%短縮、1.331倍**。
- 229.18秒の実音源でRoformer 2モデルを連続実行すると、推論合計はcold compileを含めて **112.516秒 → 87.538秒**。**22.20%短縮**。ロード込みでは114.467秒から90.217秒になった。

regional compileは34.44秒ではcold startにより既定経路より4.88%遅かった。したがって既定値は無効のままとし、実製品では目安として60秒以上の曲だけ`use_torch_compile=True`にするのが妥当である。

最終レビューで見つかったrotary embeddingの角度誤差も修正した。MPSの主要weightはfp16のまま、位置周波数だけfp32を維持する。Kim Roformer 1モデルと34.44秒区間でCPU fp32を基準にすると、出力SNRは旧経路の最小50.35 dBから新経路の最小63.81 dBへ改善した。

## 実製品のモデルチェーン

実製品の`separation_pipeline.py`に合わせ、次の4モデルを使った。DeEchoを2つのvocalへ個別適用するため、合計5推論となる。

| 順序 | モデル | アーキテクチャ | 入力 |
|---:|---|---|---|
| 1 | `mel_band_roformer_kim_ft2_bleedless_unwa.ckpt` | MDXC / MelBand Roformer | 元音源 |
| 2 | `htdemucs.yaml` | Demucs | 1のinstrument側 |
| 3 | `mel_band_roformer_karaoke_gabox_v2.ckpt` | MDXC / MelBand Roformer | 1のvocal側 |
| 4 | `UVR-DeEcho-DeReverb.pth` | VR | 3のbacking側 |
| 5 | `UVR-DeEcho-DeReverb.pth` | VR、同一instance再利用 | 3のlead側 |

製品相当設定は以下の通り。

- `use_autocast=True`
- MDXC: segment size 1101、override有効、overlap 8、batch size 1、pitch shift 0
- VR: batch size 1、window size 320、aggression 50、TTA有効、post process無効、high-end process無効
- Demucs: default segment、shifts 2、overlap 0.25、segment処理有効
- normalization 1.0、amplification 0.0

製品は中間・最終出力にm4aを使うが、モデル推論差を安定して比較するため、ベンチはWAV + soundfileに固定した。

## 測定方法

- モデルロードと推論時間を分離した。
- 各計測境界で`torch.mps.synchronize()`を呼んだ。
- Python、NumPy、PyTorch、MPSのseedを0へ固定した。
- 15秒ベンチはwarm-up 1回後、3回の中央値を採用した。
- モデルdownloadは事前に完了させた。
- `current_allocated_memory()`と`driver_allocated_memory()`は各run後の値であり、peak値ではない。
- 最終レビューのrotary修正だけの速度差は、同じprocess・同じモデルで周波数dtypeを切り替えるpaired A/Bでも測定した。15秒表と結論には補正値ではなく、最終コードを通常のベンチコマンドで直接再計測した中央値を使った。

## 採用した変更

### PyTorch 2.13をApple Siliconへ導入

依存関係だけのA/Bで、15秒の5推論合計は19.7931秒から16.5491秒へ短縮した。MPS以外には2.13を強制しないplatform markerを追加した。

### Roformer末尾chunkの重複推論を除去

末尾揃えの同一chunkを複数回forwardする場合があったため、開始位置を一意にした。34.44秒のKim Roformerは9.9129秒から7.9706秒へ19.59%短縮し、5 chunkが4 chunkになった。

### 同一モデルとVR weightを再利用

`Separator.load_model()`は同じモデルが連続した場合にinstanceを再利用し、`force_reload=True`で明示的に再ロードできる。VR networkの構築とweight loadも同じinstance内では繰り返さない。

短尺入力が一時的に有効化するsegment overrideはinstanceへ保存せず、モデル再利用後の長尺入力へ漏れないようにした。

### MelBand Roformerをnative fp16化

MPS + `use_autocast=True` + MelBand Roformerの場合だけmodel weightをfloat16化する。STFT/ISTFTとRMSNormはfloat32 islandにした。

初期実装では、fp16の`F.normalize`で既定epsilonが0へunderflowし、完全無音入力をNaN化する問題がコードレビューで見つかった。RMSNormをfloat32計算へ変更後、通常MPS経路とCPU complex fallback経路の両方でzero audioがfiniteかつ全0になることを確認した。

最終レビューでは、`model.half()`が`RotaryEmbedding.freqs`までfp16化し、系列後半の位置角度に大きな量子化誤差を生むことが見つかった。half化前のfp32値を退避し、主要weightはfp16のままrotary周波数だけfp32へ復元する。既に作られた角度cacheも破棄し、fp32値から再計算する。

### regional compileをopt-inで追加

`use_torch_compile=True`またはCLIの`--use_torch_compile`で、MelBand Roformerの反復Transformer blockだけを遅延compileする。MPS native fp16条件以外では有効化しない。
公開APIの既存位置引数をずらさないよう、`Separator`の新しい`use_torch_compile`引数は従来の引数列の末尾へ追加した。

実製品側では、Separator生成時に次のように設定できる。

```python
use_torch_compile = song_length_sec >= 60

separator = Separator(
    use_autocast=True,
    use_torch_compile=use_torch_compile,
    # ...既存設定...
)
```

60秒は今回の34.44秒と229.18秒の結果から置いた運用上の目安であり、厳密な損益分岐ではない。

### 再現可能なベンチ基盤

`tools/benchmark_mps.py`はloadと推論を分離し、同期、warm-up、反復中央値、乱数seed、MPS memory、torch・OS・git revisionをJSONへ記録する。明示的な`--device cpu/mps`指定時は内部の補助device状態も一致させる。進捗JSONはstderr、最終reportだけをstdoutへ出すため、stdoutを単一JSONとして扱える。CPUでautocastが有効な場合はbfloat16になることを警告し、fp32基準には`--no-autocast`を要求する。

## 再現コマンド

一時ディレクトリへ依存しないよう、まず元音源から入力を再生成する。`AUDIO_SEPARATOR_BENCH_PYTHON`にはPyTorch 2.13とプロジェクト依存を導入したPythonを指定する。

```bash

mkdir -p "$BENCH_ROOT/input" "$BENCH_ROOT/results"

ffmpeg -y -i "$SOURCE_DIR/oresama-pirates.wav" -ss 45 -t 15 \
  -c:a pcm_s16le "$BENCH_ROOT/input/oresama-15s.wav"
ffmpeg -y -i "$SOURCE_DIR/oresama-pirates.wav" -ss 20 -t 34.44 \
  -c:a pcm_s16le "$BENCH_ROOT/input/oresama-34s.wav"
ffmpeg -y -i "$SOURCE_DIR/LifeLight.wav" -ss 60 -t 34.44 \
  -c:a pcm_s16le "$BENCH_ROOT/input/lifelight-34s.wav"
```

既定MPS経路は次の通り。

```bash
"$AUDIO_SEPARATOR_BENCH_PYTHON" tools/benchmark_mps.py \
  "$BENCH_ROOT/input/oresama-15s.wav" \
  --model-dir "$MODEL_DIR" \
  --model mel_band_roformer_kim_ft2_bleedless_unwa.ckpt \
  --model mel_band_roformer_karaoke_gabox_v2.ckpt \
  --model htdemucs.yaml \
  --model UVR-DeEcho-DeReverb.pth \

  --autocast --no-torch-compile \
  --mdxc-segment-size 1101 --mdxc-overlap 8 --mdxc-batch-size 1 \
  --vr-batch-size 1 --vr-window-size 320 --vr-aggression 50 --vr-tta \

  --output-dir "$BENCH_ROOT/output/reproduce-final" \
```

品質表の指標は次のスクリプトで算出した。`MPS_OUTPUT`を`mps-rotary-fp16`と`mps-rotary-fp32`へ切り替えてそれぞれCPU fp32と比較する。SNRはCPU出力をsignal、MPSとの差分をnoiseとして`10 * log10(sum(signal^2) / sum(noise^2))`で求める。

```bash
MODEL_STEM=mel_band_roformer_kim_ft2_bleedless_unwa
export CPU_OUTPUT="$BENCH_ROOT/output/cpu-fp32/$MODEL_STEM"
export MPS_OUTPUT="$BENCH_ROOT/output/mps-rotary-fp32/$MODEL_STEM"

"$AUDIO_SEPARATOR_BENCH_PYTHON" - <<'PY'
import json
import os
from pathlib import Path

import numpy as np
import soundfile as sf

cpu_dir = Path(os.environ["CPU_OUTPUT"])
mps_dir = Path(os.environ["MPS_OUTPUT"])
for cpu_path in sorted(cpu_dir.glob("*.wav")):
    mps_path = mps_dir / cpu_path.name
    cpu, cpu_rate = sf.read(cpu_path, always_2d=True, dtype="float64")
    mps, mps_rate = sf.read(mps_path, always_2d=True, dtype="float64")
    if cpu.shape != mps.shape or cpu_rate != mps_rate:
        raise ValueError(f"shape/sample rate mismatch: {cpu_path.name}")

    difference = mps - cpu
    cpu_rms = np.sqrt(np.mean(np.square(cpu)))
    mps_rms = np.sqrt(np.mean(np.square(mps)))
    result = {
        "file": cpu_path.name,
        "shape": cpu.shape,
        "sample_rate": cpu_rate,
        "finite": bool(np.isfinite(cpu).all() and np.isfinite(mps).all()),
        "correlation": np.corrcoef(cpu.ravel(), mps.ravel())[0, 1],
        "snr_db": 10 * np.log10(np.sum(np.square(cpu)) / np.sum(np.square(difference))),
        "mae": np.mean(np.abs(difference)),
        "rmse": np.sqrt(np.mean(np.square(difference))),
        "max_abs_diff": np.max(np.abs(difference)),
        "rms_difference": abs(cpu_rms - mps_rms),
    }
    print(json.dumps(result, ensure_ascii=False, default=lambda value: value.item()))
PY
```
