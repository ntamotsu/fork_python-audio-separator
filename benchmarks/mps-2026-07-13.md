# MPS推論高速化ベンチマーク（2026-07-13）

## 結論

Apple M4 Pro上で、実製品が使う4モデル・5推論を対象に改善した。

- 安全性修正を含む既定経路は、15秒のwarm推論合計が **19.793秒 → 15.436秒**。**22.01%短縮、1.282倍**。
- 長尺向けregional compileを有効にすると、同じwarm推論合計は **13.517秒**。初期比 **31.71%短縮、1.464倍**。
- 各段の出力を次段へ渡す34.44秒の実チェーンは、ロード込み **44.045秒 → 32.564秒**。**26.07%短縮、1.353倍**。
- 229.18秒の実音源でRoformer 2モデルを連続実行すると、cold compileを含めても **110.617秒 → 86.831秒**。**21.50%短縮**。

regional compileは34.44秒ではcold startにより既定経路より3.19%遅かった。したがって既定値は無効のままとし、実製品では目安として60秒以上の曲だけ`use_torch_compile=True`にするのが妥当である。

PyTorch 2.13とtorchvision 0.28はDarwin arm64だけに適用した。PyTorch 2.13のmacOS wheelはmacOS 14以降を要求する。CUDA 11/12向けDocker image、Windows、Intel Macを壊さないよう、その他のplatformは従来どおりPyTorch 2.7/2.8系を解決する。

`pyproject.toml`のPython範囲は`>=3.10,!=3.14.1`である。3.14.1除外は、推移依存でも必要なtorchvision 0.28の配布条件による。

## 実製品のモデルチェーン

実製品の`separation_pipeline.py`に合わせ、次の4モデルを使った。DeEchoを2つのvocalへ個別適用するため、合計5推論となる。

| 順序 | モデル | アーキテクチャ | 入力 |
|---:|---|---|---|
| 1 | `mel_band_roformer_kim_ft2_bleedless_unwa.ckpt` | MDXC / MelBand Roformer | 元音源 |
| 2 | `htdemucs.yaml` | Demucs | 1のinstrument側 |
| 3 | `mel_band_roformer_karaoke_gabox_v2.ckpt` | MDXC / MelBand Roformer | 1のvocal側 |
| 4 | `UVR-DeEcho-DeReverb.pth` | VR | 3のbacking側 |
| 5 | `UVR-DeEcho-DeReverb.pth` | VR、同一instance再利用 | 3のlead側 |

製品相当設定は以下の通り。

- `use_autocast=True`
- MDXC: segment size 1101、override有効、overlap 8、batch size 1、pitch shift 0
- VR: batch size 1、window size 320、aggression 50、TTA有効、post process無効、high-end process無効
- Demucs: default segment、shifts 2、overlap 0.25、segment処理有効
- normalization 1.0、amplification 0.0

製品は中間・最終出力にm4aを使うが、モデル推論差を安定して比較するため、ベンチはWAV + soundfileに固定した。

## 測定方法

- モデルロードと推論時間を分離した。
- 各計測境界で`torch.mps.synchronize()`を呼んだ。
- Python、NumPy、PyTorch、MPSのseedを0へ固定した。
- 15秒ベンチはwarm-up 1回後、3回の中央値を採用した。
- モデルdownloadは事前に完了させた。
- `current_allocated_memory()`と`driver_allocated_memory()`は各run後の値であり、peak値ではない。

## 15秒・モデル単体ベンチ

入力は`oresama-15s.wav`、15.000秒、44.1 kHz、stereo、PCM 16-bit。表はロード時間を含まない。

| モデル / 推論回数 | PyTorch 2.8初期 | 2.13・コード変更前 | 安全修正後・compile無効 | regional compile warm |
|---|---:|---:|---:|---:|
| Kim Roformer ×1 | 4.6817秒 | 4.0579秒 | 3.9737秒 | 3.0104秒 |
| Karaoke Roformer ×1 | 4.6743秒 | 4.0599秒 | 3.9827秒 | 3.0270秒 |
| HTDemucs ×1 | 2.8966秒 | 2.6376秒 | 2.4996秒 | 2.4996秒 |
| DeEcho ×1 | 3.7703秒 | 2.8968秒 | 2.4899秒 | 2.4899秒 |
| DeEcho ×2 小計 | 7.5406秒 | 5.7937秒 | 4.9799秒 | 4.9799秒 |
| **5推論合計** | **19.7931秒** | **16.5491秒** | **15.4359秒** | **13.5169秒** |
| **初期比** | — | **-16.39%** | **-22.01%** | **-31.71%** |

最初のKim Roformerではcold compileを含むwarm-upが7.827秒、同一process内の2つ目のKaraoke Roformerはグラフを再利用でき、最初から3.019秒だった。

## 34.44秒・依存チェーン比較

`oresama-34s.wav`を使い、各段の実出力を次段へ渡した。旧版は`cfafc8b` + PyTorch 2.8、現行既定は安全性修正後 + PyTorch 2.13 + compile無効。各条件1回の実測である。

| 段 | 旧load | 旧推論 | 新load | 新推論 |
|---|---:|---:|---:|---:|
| Kim Roformer | 1.5334秒 | 11.2797秒 | 1.1548秒 | 8.1122秒 |
| HTDemucs | 0.0145秒 | 5.3351秒 | 0.0114秒 | 4.4995秒 |
| Karaoke Roformer | 0.9382秒 | 10.9065秒 | 0.7055秒 | 7.7453秒 |
| DeEcho / backing | 0.0235秒 | 7.2445秒 | 0.0215秒 | 5.3863秒 |
| DeEcho / lead | 0.0190秒 | 6.7509秒 | 0.000003秒 | 4.9273秒 |
| **ロード込みチェーン合計** |  | **44.0453秒** |  | **32.5638秒** |

結果は **11.4816秒、26.07%短縮、1.3526倍**。2回目のDeEcho loadがほぼ0秒なのは、連続する同一モデルを再利用するためである。

同じ34.44秒チェーンでregional compileをcold cacheから有効にすると33.6025秒だった。compile無効より3.19%遅いため、短尺では有効化しない。

## 229.18秒・regional compile比較

実音源`LifeLight.wav`全体を使い、2つのMelBand Roformerを同じprocessで連続実行した。各モデル29 chunk、warm-upなし、regional compile側は空のInductor cacheから開始した。2モデル目も同じ元音源を入力したモデル単体比較であり、製品チェーンそのものではない。

| モデル | eager | cold regional compile | 短縮率 |
|---|---:|---:|---:|
| Kim Roformer | 55.5057秒 | 45.8494秒 | 17.40% |
| Karaoke Roformer | 55.1109秒 | 40.9813秒 | 25.64% |
| **推論合計** | **110.6166秒** | **86.8307秒** | **21.50%** |
| **load込み合計** | **112.5570秒** | **89.3941秒** | **20.58%** |

全モデルcompileは15秒入力で初回18.54秒、warm 3.26秒となりcold startが大きすぎた。反復Transformer blockだけをcompileするregional方式では、初回を約7.9秒へ抑えつつwarmを約3.01秒まで短縮できたため、こちらを採用した。

## 採用した変更

### PyTorch 2.13をApple Siliconへ導入

依存関係だけのA/Bで、15秒の5推論合計は19.7931秒から16.5491秒へ短縮した。MPS以外には2.13を強制しないplatform markerを追加した。

### Roformer末尾chunkの重複推論を除去

末尾揃えの同一chunkを複数回forwardする場合があったため、開始位置を一意にした。34.44秒のKim Roformerは9.9129秒から7.9706秒へ19.59%短縮し、5 chunkが4 chunkになった。

### 同一モデルとVR weightを再利用

`Separator.load_model()`は同じモデルが連続した場合にinstanceを再利用し、`force_reload=True`で明示的に再ロードできる。VR networkの構築とweight loadも同じinstance内では繰り返さない。

短尺入力が一時的に有効化するsegment overrideはinstanceへ保存せず、モデル再利用後の長尺入力へ漏れないようにした。

### MelBand Roformerをnative fp16化

MPS + `use_autocast=True` + MelBand Roformerの場合だけmodel weightをfloat16化する。STFT/ISTFTとRMSNormはfloat32 islandにした。

初期実装では、fp16の`F.normalize`で既定epsilonが0へunderflowし、完全無音入力をNaN化する問題がコードレビューで見つかった。RMSNormをfloat32計算へ変更後、通常MPS経路とCPU complex fallback経路の両方でzero audioがfiniteかつ全0になることを確認した。

### regional compileをopt-inで追加

`use_torch_compile=True`またはCLIの`--use_torch_compile`で、MelBand Roformerの反復Transformer blockだけを遅延compileする。MPS native fp16条件以外では有効化しない。

実製品側では、Separator生成時に次のように設定できる。

```python
use_torch_compile = song_length_sec >= 60

separator = Separator(
    use_autocast=True,
    use_torch_compile=use_torch_compile,
    # ...既存設定...
)
```

60秒は今回の34.44秒と229.18秒の結果から置いた運用上の目安であり、厳密な損益分岐ではない。

### 再現可能なベンチ基盤

`tools/benchmark_mps.py`はloadと推論を分離し、同期、warm-up、反復中央値、乱数seed、MPS memory、torch・OS・git revisionをJSONへ記録する。明示的な`--device cpu/mps`指定時は内部の補助device状態も一致させる。

## 再現コマンド

既定経路は次の通り。

```bash
/private/tmp/audio-separator-torch213/bin/python tools/benchmark_mps.py \
  /private/tmp/audio-separator-bench/input/oresama-15s.wav \
  --model-dir /Users/excite2022/git/ai-concert-app_host/remote_fastapi/audio_separation/.model \
  --model mel_band_roformer_kim_ft2_bleedless_unwa.ckpt \
  --model mel_band_roformer_karaoke_gabox_v2.ckpt \
  --model htdemucs.yaml \
  --model UVR-DeEcho-DeReverb.pth \
  --device mps --warmup 1 --repeats 3 --seed 0 \
  --autocast --no-torch-compile \
  --mdxc-segment-size 1101 --mdxc-overlap 8 --mdxc-batch-size 1 \
  --vr-batch-size 1 --vr-window-size 320 --vr-aggression 50 --vr-tta \
  --demucs-shifts 2 --demucs-overlap 0.25 \
  --output-dir /private/tmp/audio-separator-bench/script/reproduce-final \
  --json-output /private/tmp/audio-separator-bench/results/reproduce-final.json
```

regional compile比較では`--no-torch-compile`を`--torch-compile`へ置き換える。製品相当5推論合計は、4つのユニークモデルのJSONから次式で算出する。

```text
Kim + Karaoke + HTDemucs + 2 * DeEcho
```
